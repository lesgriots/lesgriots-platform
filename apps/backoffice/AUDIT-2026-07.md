# AUDIT — Back Office Studio (port 3030) · Juillet 2026

Verdict global : **sain et bien pensé pour un outil solo** (stockage JSON atomique, conversion média auto Mac/Linux, badges d'alerte, slug auto, chips services). Les vrais trous : l'upload qui laisse passer des fichiers énormes (cause directe des 892 Mo du site) et zéro filet de sécurité sur les données.

> **Parti pris assumé (Moos, 07/2026)** : portfolio premium, pas de demande entrante — la reco « leads/inquiry » est retirée.

---

## P0 — CRITIQUE

### 1. L'upload ne compresse rien → c'est lui qui a produit les 892 Mo
`app/api/upload/route.js` : un JPEG de 20 Mo ou un MP4 déjà "web-compatible" est écrit **tel quel** dans `img/`. La conversion vidéo fait `-c:v copy` (remux sans réencodage) → un MOV ProRes de 70 Mo devient un MP4 de 70 Mo. Aucune limite de taille.
**Fix** :
- Images : redimensionner à max 2560px + qualité 82 systématiquement (même les .jpg/.png entrants).
- Vidéos : réencoder systématiquement en H.264 CRF 23 / 1080p max (supprimer le `-c:v copy` sauf si déjà H.264 < 10 Mbps — vérifiable via ffprobe).
- Refuser > 500 Mo avec message clair.
- Afficher le poids final + gain dans la réponse (déjà à moitié fait avec `converted`).

### 3. Zéro backup de studio.json
Une seule copie, versionnée en git mais commits manuels rares. `save()` est atomique (tmp+rename ✓) mais une suppression accidentelle + sync = perte définitive (la griothèque a un `.bak`, pas le studio).
**Fix** : dans `save()`, copier l'ancien fichier vers `backups/studio-<date>.json` (garder les 20 derniers). 10 lignes.

### 4. Mot de passe fallback "changeme"
`middleware.js:7` : si `.env.local` manque (ex : fresh clone sur le VPS), le BO tourne avec `changeme`. En prod sur admin-studio.lesgriots.com ce sera trouvé en minutes.
**Fix** : refuser de démarrer (ou 503) si `ADMIN_PASSWORD` non défini ; comparaison timing-safe (`crypto.timingSafeEqual`) tant qu'à faire.

## P1 — IMPORTANT

### 5. Pas d'état « changements non publiés »
Partout des « pense à re-sync » en texte. Facile d'éditer, fermer, et laisser le site désynchronisé des jours.
**Fix** : stocker `last_export_at` dans studio.json ; comparer au `updated_at` max ; badge « ● N modifs non publiées » sur le bouton Sync dans la topbar.

### 6. Pas de garde-fou sur le formulaire projet
Aucun `beforeunload` : 20 min de saisie + un clic sur « Projets » = tout perdu. Le bouton « Annuler » ne demande rien.
**Fix** : dirty-check + `onbeforeunload` + confirm sur Annuler. ~15 lignes.

### 7. Réordonnancement pénible et fragile
`page.jsx move()` : un cran par clic + un PUT par projet changé, séquentiels. Réordonner 15 projets = des dizaines de clics ; un PUT qui échoue au milieu = ordre incohérent silencieux.
**Fix minimal** : endpoint `POST /api/projects/reorder` (bulk, un seul write). **Fix confort** : drag & drop HTML5 natif (pas de lib nécessaire).

### 8. PUT crée silencieusement un projet inexistant
`api/projects/[id]/route.js` : PUT → `upsertProject` sans vérifier l'existence. Une typo d'URL crée un doublon fantôme.
**Fix** : 404 si `getProject(id)` est null.

### 9. Upload sans feedback de progression
Un MP4 de 300 Mo = bouton figé sans indication, erreur affichée en bas de page (invisible). **Fix** : `XMLHttpRequest`/`fetch` + barre de progression dans `MediaInput`, erreur affichée à côté du champ concerné.

### 10. Aucune gestion des médias orphelins
Supprimer un projet ne touche pas ses fichiers dans `img/` ; rien ne liste ce qui traîne. C'est comme ça qu'on accumule screenshots de 17 Mo et doublons.
**Fix** : page `/media` : liste `img/*` avec poids, marque ceux référencés par aucun projet, bouton supprimer. Complément direct du Sprint 2 du site.

### 11. Pas de recherche/filtre dans la liste projets
OK à 12 projets, pénible à 30. **Fix** : input filtre client-side (nom/client/tag) + tri par colonne. ~30 lignes.

## P2 — MINEUR

12. README ment : dit « SQLite (better-sqlite3) » alors que c'est du JSON pur — à corriger avant de passer le repo à un dev.
13. Preview vidéo sans `controls` dans MediaInput → impossible de vérifier le contenu uploadé. Ajouter `controls muted`.
14. Pas de bouton « Dupliquer » un projet (utile pour projets similaires).
15. `getDb()`/`rowToProject`/`projectToRow` : vestiges SQLite morts dans db.js — supprimer.
16. `/api/preview` sert tout le dossier site (code inclus) — derrière auth, acceptable, mais restreindre à `img/` + `fonts/` serait plus propre.
17. Pas de champs SEO (meta description, og:image) éditables — à ajouter quand le site aura ses balises (Sprint 3 site).
18. Table non responsive — le BO est inutilisable sur téléphone (acceptable si usage desktop only, à trancher).

## Ce qui est déjà bien
Écriture atomique tmp+rename · conversion HEIC/MOV multi-outils avec fallbacks et messages d'erreur actionnables · protection path-traversal sur /api/preview · badges qualité (sans cover, média non-web) · slug auto depuis le nom · chips services · cache-bust auto de data.jsx dans index.html à l'export · placeholder SVG pour covers manquantes · conflit d'id refusé en création.
